# Awoo 狼人殺 — Step 9.3（系統自動上帝主持）

本階段延續 Step 6，加入本機測試模式與全角色控制台巡檢功能。目標是降低後續新增角色、改玩法與修 Bug 的連動風險。本專案目前仍是本機原型，尚不是多人連線版。

## 專案結構

- `index.html`：頁面結構與現有遊戲介面。
- `css/styles.css`：整體風格與各畫面元件樣式。
- `js/role-database.js`：角色 metadata、別名、陣營、技能說明、角色關係及版本差異。
- `js/ruleset.js`：標準房規與驗證；集中管理勝利模式、警長票權重、守衛／解藥互動，以及小狼自爆的開關、角色白名單與可發動階段。
- `js/game-engine.js`：不依賴 DOM 的核心規則，包括角色池驗證、發牌、夜間行動驗證、夜晚結算、小狼自爆驗證與執行、勝負判定及投票結算。
- `js/game-flow.js`：合法回合階段轉換、環狀座位的發言順序與下一位發言者計算。
- `js/moderator-script.js`：依本局角色組合與夜數建立上帝口白；支援 Awoo 預設順序及 classic 替代順序。
- `js/compendium.js`：角色圖鑑搜尋、陣營篩選、詳情與角色關係跳轉。使用 DOM API 和 `textContent` 建立角色資料畫面，避免把角色文字直接拼接進 HTML。
- `js/ui.js`：通用 UI helper，例如安全 HTML 跳脫、文字更新、面板顯示與公告欄更新。
- `js/app.js`：瀏覽器控制器，連結使用者操作、計時器、遊戲引擎及畫面更新；未來仍會繼續拆分。
- `docs/ADDING_ROLES.md`：新增角色與技能的維護規範。
- `docs/ARCHITECTURE.md`：模組職責、資料流程與回歸測試方向。
- `docs/TEST_MODE.md`：全角色測試模式操作、快速流程控制與巡檢建議。
- `docs/MODERATOR_SCRIPT.md`：角色式上帝口白、夜間順序、私密資訊及規則差異說明。
- `tests/*.test.cjs`：使用 Node.js 的自動化測試。

## 開啟與測試

直接以瀏覽器開啟 `index.html` 可以檢視前端原型。若瀏覽器限制本機檔案或媒體權限，請用本機靜態 HTTP 伺服器提供檔案。麥克風／攝影機需要 HTTPS 或 localhost；多人視訊仍需訊令伺服器與 WebRTC 實作。

需要 Node.js 18 或更新版本，在專案根目錄執行：

```bash
node --test tests/*.test.cjs
```

也可以執行 `npm test`（不需要安裝第三方套件），或用 `npm run check` 一次執行語法檢查與自動化測試。

截至 2026-10-25，最新 GitHub Actions `Awoo checks` 通過 104/104 項 Node.js 自動化測試與 8 個 JavaScript 模組語法檢查（[CI 紀錄](https://github.com/ivi39c/awoo/actions/runs/40174160926)）。測試涵蓋角色視角與隊友顯示、夜間目標隱私、主持口白／行動鎖定、女巫藥劑結算、死亡公告、共用選人介面及可收合行動紀錄；這仍不等於完整真實瀏覽器或手機實機端到端測試。

## Step 7 本階段完成

1. 新增獨立的測試模式入口；測試模式以 12 個座位啟動本機 Bot 測試局。
2. 頂部視角切換器只在測試模式顯示與啟用；一般模式拒絕切換其他座位視角。
3. 對局發牌後，控制台提供角色覆蓋下拉選單，可把目前視角座位替換為角色資料庫中的任一角色，以巡檢各階段的控制面板。
4. 顯示角色控制台巡檢進度與技能接入狀態；清楚區分圖鑑已收錄和專屬技能已實作。
5. 測試模式新增立即結算夜晚、跳過發言、結束警長競選倒數、立即結算公投、結束遺言及重新開始測試局等輔助操作。
6. 新增 `docs/TEST_MODE.md`，提供測試流程與建議巡檢清單。
7. 新增測試模式自動化測試；目前共 43 項 Node.js 自動化測試通過。

## 前序階段保留功能

1. 新增 `ruleset.js`，提供標準房規、房規覆寫及驗證。
2. 小狼可在房規允許的白天階段自爆；引擎驗證角色、存活狀態與時機後，將其標記為因自爆出局，清除當日發言／投票／遺言流程並直接進入下一夜。若自爆使遊戲立即達成終局勝利，則直接結束遊戲。
3. 自爆預設只對「小狼」開放；狼王、白狼王等角色需各自實作技能，不會自動套用。
4. 將圖鑑渲染抽離至 `compendium.js`，搜尋與分類以事件監聽器處理，不再依賴散落在 HTML 的 inline handler。
5. 圖鑑文字以 DOM 元素與 `textContent` 呈現；角色間的可解析關係會成為可點擊的跳轉按鈕。
6. 加入 `game-flow.js`，主程式的階段改由轉換器驗證，並把發言順序計算從 `app.js` 抽離。
7. 加入無警長分支的「夜晚 → 天亮結算 → 白天發言」階段轉換，避免嚴格階段圖阻斷該流程。
8. 新增圖鑑、回合流程、房規與自爆測試，更新模組載入順序測試。

## 已知限制

- `app.js` 仍包含房間原型、計時器、警長流程、音訊／視訊控制、夜間面板及投票流程；尚未全部拆分。
- 圖鑑收錄不等於技能可玩，許多特殊角色仍只有 metadata，沒有對應遊戲引擎效果。
- 自訂板型尚未提供完整的每角色數量／規則配置介面。
- 警長競選目前不是完整的多人投票機制，尚無完整平票與退出競選流程。
- 加入房間仍為本機模擬，不會讓不同瀏覽器共享同一狀態。
- 尚未完成多人伺服器端權限、房間狀態持久化、斷線重連與 WebRTC。
- 自動化測試不是完整的真人瀏覽器遊戲測試；發布前仍需實際驗證開局、完整多日流程、不同規則與媒體權限。

## 已知限制與下一步

- 角色覆蓋會直接修改本機測試局角色，可能影響陣營數量與勝負條件，請勿用於正式對局。
- 多數圖鑑角色仍只有資料卡，尚未具備專屬技能控制項；測試面板會顯示待實作提示。
- 自動化測試未替代真實瀏覽器完整流程驗收；請依 `docs/TEST_MODE.md` 手動跑過一局並回報結果。
- 後續將繼續完善特殊角色技能與房規 UI，再導入伺服器權威狀態、多人同步、身分權限與 WebRTC。


## Step 9：女巫毒藥與上帝口白

- 女巫毒藥改用座位選擇器：所有玩家號碼可見，已出局座位反灰且無法選取；確認後才消耗毒藥。
- 修正夜間死亡直接觸發勝負時未播報死訊的流程。遊戲結束公告會一起說明本夜實際出局玩家。
- 新增 `moderator-script.js`，依本局角色與夜數產生上帝口白，並用瀏覽器繁體中文語音合成逐句朗讀。
- 預設順序為狼人 → 女巫 → 預言家 → 守衛；`classic` 順序可選守衛 → 狼人 → 女巫 → 預言家。不同來源和板型規則不一致，請在開局時固定選定版本。
- 新增毒藥端到端整合測試與主持流程測試；目前 `npm run check` 為 55/55 通過。

## Step 9.3：系統自動上帝主持

- 正式模式不再顯示人工主持人的「下一句」、重播或手動確認按鈕。上帝口白播放結束後，無需決策的提示會自動推進。
- 狼人、女巫、預言家與守衛等已接入的主動技能，必須先完成合法操作；操作完成後系統會自動播放下一句，不需要主持人點擊。
- 首夜若配置狼王，狼人互認後加入「狼王請比讚。」手勢提示，再進入狼隊選刀；沒有狼王時不會播放該句。
- 測試模式仍保留手動逐句推進、重播、視角切換及未實作技能的佔位流程確認。
- 正式模式會阻止尚有主動夜間技能佔位流程的板型開始，以免正式對局卡在沒有實際操作控制項的步驟。
- 提醒倒數結束不會略過技能或提前結算夜晚。
- `npm run check` 通過 75/75 Node.js 測試及 8 個 JavaScript 模組語法檢查。
