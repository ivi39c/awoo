# 新增與維護角色的規範

## 1. 先確認是否為既有角色的別名

新增前先搜尋 `ROLE_DATABASE` 的 `name` 與 `aliases`。若只是不同平台的譯名，優先增加 `aliases`，避免把同一角色重複建立成兩份資料。若同名角色在不同版本的技能確實不同，應使用清楚的版本標籤或不同的 canonical name，而不是覆寫既有定義。

## 2. 角色資料欄位

每筆角色由 `makeRole(name, team, category, ability, extra)` 建立，基本欄位如下：

- `name`：唯一、穩定的標準名稱。
- `team`：`wolf`、`wolfAlly`、`good`、`couple` 或 `third` 之一。
- `category`：例如 `神職`、`平民`、`特殊`。
- `ability`：以可讀文字描述技能；不要把未確認的版本差異寫成通用規則。
- `aliases`：別名、常見譯名或英文名。
- `timing`：行動時機。
- `relations`：與本資料庫其他角色的直接互動或規則相關角色。
- `interaction`：結算衝突、技能相剋、資訊呈現等注意事項。
- `variants`：版本、平台或房規差異。
- `implementation`：標示「僅圖鑑收錄」、「原型已接入」、「已測試」等實際狀態；不能因為出現在圖鑑就宣稱技能已可用。

## 3. 新增步驟

1. 把角色加入 `js/role-database.js` 的正確分類區。
2. 填寫技能、時機、關係與版本差異；若來源不足，明確標為待確認。
3. 透過 `relations` 使用角色標準名稱，並執行資料測試。
4. 確認別名不會把另一角色的名稱映射到錯誤角色。
5. 若角色需要可操作技能，另外在遊戲引擎中實作並加上測試；不要只修改圖鑑文字。
6. 在實際對局中驗證首次發動、死亡狀態、技能互相作用、平票／勝負時機與多夜狀態清理。

## 4. 擴充玩法的原則

可配置的房規（例如守衛連守、女巫自救、警長票權重、技能使用次數與小狼自爆窗口）應集中在 `js/ruleset.js`，而不是散落在 UI 事件中。技能應透過遊戲引擎定義行動窗口、合法目標、效果與結算順序；UI 僅負責顯示合法行動並提交選擇。伺服器版上線後，最終驗證必須由伺服器進行。

## 5. 與遊戲引擎的責任分界

`js/role-database.js` 只描述角色 metadata；不要在角色資料庫內操作 DOM 或執行遊戲狀態變更。角色若要真正加入對局，請在 `js/game-engine.js` 明確實作相對應的行動驗證、效果／狀態變更、結算先後次序與測試案例。`js/ui.js` 只處理通用畫面操作，`js/app.js` 收集玩家輸入並呼叫引擎，不應自行發明另一套技能規則。

每個新增技能至少加入以下測試案例：合法角色與合法目標、非法角色、目標已死亡、技能已使用、技能與另一效果同時發生，以及該技能導致的勝負判定。對於跨平台有差異的技能，請把規則寫入明確的 ruleset 選項，並測試不同設定，不要依賴隱含的預設行為。
