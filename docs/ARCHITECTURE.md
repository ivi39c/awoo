# Awoo 架構與維護指南

## 模組分工

| 模組 | 可以做 | 不應做 |
|---|---|---|
| `role-database.js` | 描述角色、陣營、別名、技能概要、互動關係與版本差異 | 變更對局狀態、操作 DOM、宣稱圖鑑角色一定可玩 |
| `ruleset.js` | 提供房規預設值、覆寫與資料驗證 | 直接操作 DOM 或自行改動玩家存活狀態 |
| `game-engine.js` | 驗證行動、結算技能與投票、判斷勝負 | 使用 `document`、`alert`、計時器或媒體 API |
| `game-flow.js` | 管理合法階段轉換、發言次序等不依賴 DOM 的流程規則 | 操作畫面、開計時器或取得玩家媒體 |
| `compendium.js` | 搜尋、篩選與呈現角色資料、處理角色關係跳轉 | 修改實際對局角色、直接決定技能結果 |
| `ui.js` | 可重用的 DOM helper 與公告更新 | 擁有遊戲規則與勝負條件 |
| `app.js` | 收集 UI 操作、管理計時器、呼叫引擎並更新介面 | 用另一套條件判斷重複實作技能與勝負規則 |

## 主要資料流

1. 玩家由 UI 選擇行動。
2. `app.js` 傳送玩家、行動、目標與當前階段給 `game-engine.js` 驗證。
3. 合法行動才寫入遊戲狀態；夜晚結束時由引擎統一結算。
4. `game-flow.js` 驗證目前階段能否轉到下一階段，並計算發言隊列。
5. `app.js` 讀取結果並請 `ui.js` 或各畫面模組更新顯示。

正式多人版中，第 2 與第 3 步必須由伺服器執行；瀏覽器端驗證只能改善體驗，不能作為安全邊界。

## 新增角色

1. 在 `role-database.js` 新增一筆唯一的 canonical role 資料，確認別名不與其他角色衝突。
2. 寫清楚技能時機、目標、作用範圍、結算優先級、死亡後效果與版本差異。
3. 若角色只需顯示在圖鑑，可先標示「僅圖鑑收錄」。
4. 若要進入對局，必須在 `game-engine.js` 補上行動驗證、狀態變更與結算，並更新必要的牌池或勝負條件。
5. 測試一般情境、非法目標、目標死亡、技能使用次數耗盡、同夜技能衝突、死亡觸發與勝負條件。

## 新增玩法

新玩法優先新增一個可明確命名的 `ruleset` 選項，不要把規則藏在 UI 事件裡。例如：

- `winMode`: `edge` 或 `parity`。
- `guardAndSaveSameTargetDies`: 守衛與女巫同時保護時的結果。
- `witchCanSelfSave`: 女巫是否可自救。
- `sheriffWeight`: 警長票權重。
- `wolfSelfDestructEnabled`, `wolfSelfDestructRoles`, `wolfSelfDestructPhases`: 是否啟用小狼自爆、哪些角色可用、哪些白天階段可中斷並直接進入夜晚。

新增選項後，需有預設值、UI 設定、引擎驗證與正反兩種測試。規則名稱和可用值應在 docs 中同步維護。

## 發版前的最低檢查

```bash
node --test tests/*.test.cjs
```

並且在瀏覽器手動走過：建房／快速測試、發牌、夜晚行動、天亮、無警長發言、警長發言、投票平票、處決與遺言、遊戲結束。需要媒體功能時，再測試拒絕權限、允許權限與關閉裝置後的狀態。
