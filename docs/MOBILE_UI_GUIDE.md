# Awoo Step 8：手機優先 UI 驗收指南

本階段先更新視覺樣式與主要導覽，不應視為最終 UI 定稿。請在正式多人開發前先手動驗收並回報操作問題。

## UI 方向

- **風格**：暗黑哥德氛圍，但降低大面積金色邊框、陰影與發光，優先可讀性。
- **手機資訊層級**：頂部房間／工具列 → 回合階段公告 → 座位表 → 底部操作抽屜 → 固定底部導覽。
- **主要操作**：角色操作與投票目標要大、可點；面板內容可獨立捲動，不讓手機導覽遮住按鈕。
- **桌面延伸**：寬螢幕增加座位欄數、回復桌面置中 modal 和右下角控制台，不另外維護一套邏輯。

## 建議驗收 viewport

| 裝置／viewport | 需要檢查 |
|---|---|
| 320 × 700 | 座位卡文字是否過度擠壓、頂部工具是否可橫向滑動、底部抽屜與導覽是否重疊 |
| 375 × 812 | 大廳按鈕、階段公告、座位表與底部導覽 |
| 390 × 844 | 控制台開合、目標選取、女巫控制項、圖鑑 modal |
| 430 × 932 | 三欄切換前的兩欄密度、圖鑑搜尋和角色詳情 |
| 768 × 1024 | 平板是否切到適合的座位卡與桌面工具排列 |
| 1366 × 768 | 桌面頂部工具列、四欄／五欄座位表、右下角控制面板 |

## 建議功能流程

1. 初次載入：檢查大廳在手機上不需水平捲動，所有主按鈕容易按到。
2. 點「測試模式」：測試橫向工具列、角色視角 select 和巡檢 banner 在窄螢幕是否可讀。
3. 開始遊戲：檢查階段公告與座位卡，底部控制抽屜不要遮住必要資訊。
4. 夜間行動：每個目標按鈕保持足夠觸控尺寸，面板可上下捲動。
5. 白天自爆：測試按鈕不被底部 dock 或視窗安全區遮住，確認能立即進入下一夜。
6. 投票：測試目標選取狀態、確認投票、棄票和出局玩家不可投票。
7. 圖鑑：搜尋、分類、點關係跳轉；確認小螢幕上列表和詳情都能捲動。
8. 影音：測試權限允許／拒絕提示。當前只預期本機裝置測試，不會有遠端畫面。
9. 桌面：確認 mobile dock 隱藏，桌面工具列、角色卡片和 modal 仍可正常使用。

## 注意事項

- 先使用測試模式，角色替換會直接修改當前本機測試狀態，不可用於真實對局公平性驗證。
- 新版 UI 尚未經過 iOS Safari／Android Chrome 實機驗收；CSS 靜態測試通過只證明必要規則存在。
- 若畫面在手機直向或橫向中發生重疊，記錄 viewport、目前階段、操作步驟與截圖，便於逐項修正。
